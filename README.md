# Healthcare Patient Flow Analytics

This project analyzes a year of synthetic outpatient appointment and capacity data for a
fictional clinic. It looks at patient volume, waiting time, appointment outcomes and how
much provider capacity is booked and used. It is a data analytics portfolio project that
takes the data from generation through SQL analysis to an Excel report and a Power BI
dashboard.

> **Synthetic data only, not for clinical use.** All patients, providers, appointments and
> clinic details are fictional and were generated by `generate_data.py`. The repository
> contains no real patient information. It is meant for portfolio and educational use and
> must not be used for clinical or operational decisions.

![Operational Overview dashboard page](screenshots/powerbi_operational_overview.png)

## Main features

- Deterministic synthetic data: the same seed always produces the same appointments,
  schedules, patients and providers.
- A validation and cleaning step that stops with a list of problems instead of guessing a
  fix.
- Processed CSV files and a SQLite database with keys and CHECK constraints.
- A JSON data-quality report.
- Six SQL views for the KPIs, checked by 37 reconciliation tests before export.
- An Excel report built with openpyxl: 8 sheets, rate formulas, Excel tables and three
  charts.
- A three-page Power BI dashboard on a star-schema model with 16 DAX measures.
- pytest tests covering generation, validation, analytics, both reports and repository
  integrity.

## Key results (seed 42)

These are the headline KPIs for calendar year 2025 (01/01/2025–12/31/2025). The SQL
views, the Excel workbook, `powerbi/expected_kpis.json` and the dashboard cards all give
the same values.

| KPI | Value |
|---|---|
| Total Appointments | 5,000 |
| Unique Patients | 1,229 |
| Completed / Cancelled / No Show | 4,000 / 573 / 427 |
| Completion Rate | 80.0% |
| Cancellation Rate | 11.5% |
| No Show Rate | 8.5% |
| Average Wait Minutes (Completed) | 29.7 |
| Average Visit Minutes (Completed) | 32.0 |
| Available Slots | 6,956 |
| Booking Rate | 71.9% |
| Completed Slot Utilization | 57.5% |

What the data shows:
- **Booked vs completed capacity.** 71.9% of available slots were booked, but only 57.5%
  became completed visits. The 14.4-point gap is the 1,000 cancelled and No Show
  appointments.
- **Departments.** Family Medicine had the highest booking rate (86.3%) and Dermatology
  the lowest (62.5%). Dermatology also had the highest No Show rate (12.4%), and
  Cardiology the lowest (4.7%).
- **Waiting time.** The average wait was longest in Neurology (37.4 minutes) and shortest
  in Pediatrics (24.0 minutes).
- **Seasonality.** January was the busiest month (481 appointments) and June the quietest
  (365).
- **Weekdays.** Tuesday had the most appointments (1,419). It also had the most scheduled
  capacity (1,900 slots), because the providers who hold clinic on Tuesday have the
  largest combined daily capacity. By booking rate, Monday was highest (76.2%) and Friday
  lowest (62.3%).

These results come from the rules in the generator's settings (`config.py`), such as
seasonal demand and department-level No Show rates. They show that the analysis finds and
measures patterns like these. They do not describe a real healthcare organization.

### KPI definitions

SQL, Excel and DAX all use the same definitions.

| KPI | Definition |
|---|---|
| Total Appointments | All appointment records, every status |
| Unique Patients | Distinct patients with at least one appointment |
| Completed / Cancelled / No Show Appointments | Appointments with that `appointment_status` |
| Completion / Cancellation / No Show Rate | That status count / Total Appointments |
| Average Wait Minutes | Average `wait_minutes` (check-in to seen), Completed only |
| Average Visit Minutes | Average `visit_minutes` (seen to checkout), Completed only |
| Available Slots | Sum of `provider_schedules.available_slots` |
| Booking Rate | Total Appointments / Available Slots |
| Completed Slot Utilization | Completed Appointments / Available Slots |

A few calculation rules matter when reading the numbers:
- Every appointment used a slot when it was booked, whatever happened later. Booking Rate
  therefore counts all statuses, while Completed Slot Utilization counts only completed
  visits.
- A rate is blank when its denominator is 0 (SQL `NULL`, an empty Excel cell, DAX
  `DIVIDE`).
- Overall rates use overall counts. They are never an average of department percentages.
- Wait time starts at the actual check-in, which can be earlier than the scheduled time.
- Capacity metrics can be filtered by date, department and provider. They do not apply to
  appointment type or patient group.

## Project workflow

Synthetic data generation → validation and cleaning → SQLite database → SQL analytics →
Excel report → Power BI data package → Power BI dashboard.

```
generate_data.py         synthetic raw CSV files (seed 42)              data/raw/
       │
prepare_data.py          validate -> clean -> SQLite + quality report    data/processed/, data/output/
       │
analyze_data.py          SQL KPI views -> reconciliation -> CSV exports  data/output/analytics/
       │
create_excel_report.py   Excel report (values from SQL, rate formulas)   reports/
       │
prepare_powerbi_data.py  Power BI snapshot + reference KPIs              powerbi/data/, powerbi/expected_kpis.json
       │
Power BI Desktop         three-page dashboard (built by hand)            powerbi/*.pbix, screenshots/
```

Each script after generation checks its input and stops with a clear message if anything
does not reconcile.

<details>
<summary>How the synthetic data is generated</summary>

- **Period:** calendar year 2025, weekdays only. Clinic days start at 08:00 with 30-minute
  slots.
- **Departments and providers:** 6 departments with 2 fictional providers each. Each
  provider works fixed weekdays. The number of clinic days is set so that about 75% of
  slots are booked, and a few days have reduced or zero slots.
- **Demand:** busier in winter and early in the week. Department demand, No Show rates
  and cancellation rates differ by design.
- **Completed visits:** patients check in between 20 minutes early and 10 minutes late;
  waits grow later in the day and on Mondays; visit length depends on appointment type.
- **Cancelled and No Show appointments:** these have no check-in, seen or checkout times.
- **Patients:** Pediatrics sees only patients under 18, and other specialist departments
  see adults. A patient has at most one appointment per day.
- **Settings:** all of them live in `config.py`.

</details>

<details>
<summary>Validation rules in <code>prepare_data.py</code></summary>

The only automatic fix is trimming spaces around values. Any other problem stops the
pipeline with a list of problems and example IDs, writes a "failed" quality report, and
leaves the processed folder unchanged.

The checks cover:
- required columns and values;
- unique primary keys;
- foreign keys;
- each appointment falls on a scheduled clinic day;
- appointment and schedule departments match the provider's department;
- age is 0–120 and the age group matches the age;
- valid status and type values;
- positive provider capacity, and schedule slots between 0 and the provider's capacity;
- bookings never exceed the available slots;
- Completed times are ordered check-in ≤ seen ≤ checkout;
- Cancelled and No Show times are blank.

After loading, the script checks that row counts match the CSV files and runs SQLite
`PRAGMA foreign_key_check`.

</details>

<details>
<summary>SQLite database and SQL views</summary>

The database (`data/processed/healthcare_analytics.db`) is rebuilt by `prepare_data.py`.

| Table | Grain | Primary key |
|---|---|---|
| `departments` | department (6) | `department_id` |
| `providers` | provider (12) | `provider_id` |
| `patients` | patient (1,250) | `patient_id` |
| `provider_schedules` | provider clinic day (626) | `schedule_date` + `provider_id` |
| `appointments` | appointment (5,000) | `appointment_id` |

The schema (`sql/01_create_schema.sql`) has foreign keys, including each appointment to
its provider's clinic day. It also has CHECK constraints on ages, capacities, status
values, date formats, time order and non-negative durations, plus indexes for the common
filters.

The KPI views are in `sql/02_create_analytics_views.sql`:

| View | One row per | Capacity metrics |
|---|---|---|
| `vw_overall_kpis` | whole dataset (with reporting period, unique patients) | Yes |
| `vw_monthly_trends` | month | Yes |
| `vw_department_performance` | department | Yes |
| `vw_provider_performance` | provider | Yes |
| `vw_appointment_type_performance` | appointment type | No |
| `vw_weekday_activity` | weekday (1 = Monday) | Yes |

Each view counts appointments and adds up capacity separately before joining them, so
neither side is multiplied. `analyze_data.py` runs 37 reconciliation checks before it
exports one CSV file per view, for example that every breakdown adds up to the overall
totals.

</details>

<details>
<summary>Power BI data model</summary>

Details are in [POWER_BI_DATA_MODEL.md](powerbi/POWER_BI_DATA_MODEL.md).
- Fact tables: Appointments and ProviderSchedules.
- Dimensions: Date, Departments, Providers and Patients.
- Relationships: six active, one-to-many, single-direction relationships. Department
  filters both fact tables through Providers.

</details>

## Getting started

You need:
- Python 3.12 (the version the project was tested with) and Git;
- Power BI Desktop, only if you want to open the `.pbix` dashboard;
- Microsoft Excel, optionally, for viewing the `.xlsx` report.

Clone the repository and install the pinned packages in Windows PowerShell:

```powershell
git clone https://github.com/nareshvemula022/healthcare-patient-flow-analytics.git
cd healthcare-patient-flow-analytics
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Calling `.\.venv\Scripts\python.exe` directly means you don't have to activate the
virtual environment. If `python` on your computer is a different version, the Windows
Python launcher can create the environment instead: `py -3.12 -m venv .venv`.

Then run the pipeline in order:

```powershell
.\.venv\Scripts\python.exe generate_data.py --appointments 5000 --seed 42
.\.venv\Scripts\python.exe prepare_data.py
.\.venv\Scripts\python.exe analyze_data.py
.\.venv\Scripts\python.exe create_excel_report.py
.\.venv\Scripts\python.exe prepare_powerbi_data.py
```

Before you run them, note which tracked files they change:
- The first three scripts write only to `data\`, which Git ignores.
- `prepare_powerbi_data.py` rewrites `powerbi\data\` and `powerbi\expected_kpis.json`
  with identical content.
- `create_excel_report.py` replaces the tracked workbook in `reports\`. The content is the
  same, but the file bytes change (timestamps), so Git shows it as modified. To leave the
  tracked copy alone, write somewhere else with
  `.\.venv\Scripts\python.exe create_excel_report.py --output <another path>`. If the
  workbook is open in Excel, close it first.

`generate_data.py` also accepts `--patients` and `--output-dir`. The other scripts accept
input and output paths; run any of them with `--help` to see the options.

The `data/` folders start empty after cloning. Running the first three pipeline scripts
recreates everything in them.

**Excel report.** Open it in Excel. Its sheets are:
- Summary: the 13 KPIs with definitions, and three charts.
- Monthly Trends, Department Analysis, Provider Analysis and Appointment Types: one row
  per group, with a Total row.
- Data Quality: an audit sheet with the validation results and the 37 reconciliation
  checks.
- Appointment Data and Capacity Data: filterable Excel tables of the underlying rows.

Counts and averages come from the SQL views. Rates are Excel formulas such as
`=IF(B5=0,"",C5/B5)`, with explicit numerator and denominator cells, so they never show
`#DIV/0!`.

**Power BI dashboard.** Open the `.pbix` file in Power BI Desktop. If it cannot find the
CSV files on your computer, point the data source to your `powerbi\data` folder under
**Transform data > Data source settings**.

**SQL analytics.** After `analyze_data.py` has run, the views can be queried in
`data/processed/healthcare_analytics.db` with any SQLite client, or read as CSV files in
`data/output/analytics/`.

**Power BI documentation:**
- [POWER_BI_DATA_MODEL.md](powerbi/POWER_BI_DATA_MODEL.md): tables, relationships and
  filter directions.
- [DATA_DICTIONARY.md](powerbi/DATA_DICTIONARY.md): every Power BI column with its type,
  meaning, key and blanks.
- [dax_measures.txt](powerbi/dax_measures.txt): the 16 DAX measures with their formats.

## Limitations

- **Synthetic data for one fictional clinic.** The patterns were designed into the
  generator, so the results show the method rather than real-world findings. Waiting and
  visit times are simulated, and insurance categories use US-style labels.
- **One year of data.** It covers calendar year 2025 only.
- **Weekday schedules only.** There is no public-holiday calendar.
- **The PBIX was built manually** in Power BI Desktop. The automated tests check its data
  snapshot and files, not the report's internal settings.
- **Power BI source paths** may need to be repointed on another computer (see
  [How to use the outputs](#how-to-use-the-outputs)).
- **The workbook is generated by openpyxl.** Excel recalculates the rate formulas when it
  opens the file. Its author fields are set to "Healthcare Patient Flow Analytics".
  Saving the file from Excel would record the Excel user's name instead, so regenerate it
  with the script rather than saving it in Excel.

The dashboard was accepted as built, with a few formatting choices that differ from the
original plan: automatic visual titles, count cards without thousands separators, a
monthly line chart whose axis does not start at zero, and no on-canvas synthetic-data
notice. Average Visit Minutes and Cancellation Rate are in the model but not on a card.
These are listed in the
[verification checklist](powerbi/POWER_BI_VERIFICATION_CHECKLIST.md#accepted-design-choices).
