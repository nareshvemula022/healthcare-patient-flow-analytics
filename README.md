# Healthcare Patient Flow & Operational Analytics Platform

An end-to-end data analytics portfolio project for a fictional outpatient clinic. It
generates a synthetic year of appointment data, then validates and cleans it with Python,
loads it into a SQLite database, and calculates the KPIs in SQL. The results are reported
in an Excel workbook and a three-page Power BI dashboard. The analysis covers patient
volume, appointment status, waiting time, and provider and department capacity.

> **Synthetic data only: not for clinical use.** Every record is generated by
> `generate_data.py` with a fixed random seed. Patients, providers, departments, cities
> and times are fictional. Nothing in this repository comes from, represents or describes
> a real person, hospital or clinic. It is not medical data and must not be used for
> clinical or operational decisions.

## Project objectives

The project answers these operational questions for the fictional clinic:

1. How many appointments and patients were there, and what share were completed,
   cancelled or missed (No Show)?
2. How long do patients wait between check-in and being seen, and how long do visits last?
3. How much provider capacity was booked, and how much of it became a completed visit?
4. How do volume and capacity change by month and weekday?
5. How do departments and providers compare on booking rate, No Show rate and waiting
   time?
6. How do appointment types and patient groups differ in volume and status mix?

## Workflow

```
generate_data.py         synthetic raw CSV files (seed 42)              data/raw/
       │
prepare_data.py          validate -> clean -> SQLite + quality report    data/processed/, data/output/
       │
analyze_data.py          SQL KPI views -> reconciliation -> CSV exports  data/output/analytics/
       │
create_excel_report.py   Excel report (values from SQL, rate formulas)   reports/
       │
prepare_powerbi_data.py  Power BI snapshot + reference KPIs              powerbi/data/, powerbi/expected_kpis.json
       │
Power BI Desktop         three-page dashboard (built by hand)            powerbi/*.pbix, screenshots/
```

Every step after generation checks its input and stops with a clear message if anything
does not reconcile.

## Key results (seed 42)

Headline KPIs for calendar year 2025 (01/01/2025–12/31/2025). The SQL views, the Excel
workbook, `powerbi/expected_kpis.json` and the dashboard cards all give the same values.

| KPI | Value |
|---|---|
| Total Appointments | 5,000 |
| Unique Patients | 1,229 |
| Completed / Cancelled / No Show | 4,000 / 573 / 427 |
| Completion Rate | 80.0% |
| Cancellation Rate | 11.5% |
| No Show Rate | 8.5% |
| Average Wait Minutes (Completed) | 29.7 |
| Average Visit Minutes (Completed) | 32.0 |
| Available Slots | 6,956 |
| Booking Rate | 71.9% |
| Completed Slot Utilization | 57.5% |

What the synthetic data shows:
- **Booked vs completed capacity:** 71.9% of available slots were booked, but 57.5% became
  completed visits. The 14.4-point gap is the 1,000 cancelled and No Show appointments.
- **Departments:**
  - Family Medicine had the highest booking rate (86.3%) and Dermatology the lowest
    (62.5%).
  - Dermatology also had the highest No Show rate (12.4%), and Cardiology the lowest
    (4.7%).
- **Waiting time:** average wait was longest in Neurology (37.4 minutes) and shortest in
  Pediatrics (24.0 minutes).
- **Seasonality:** January was the busiest month (481 appointments) and June the quietest
  (365).
- **Weekdays:**
  - Tuesday had the most appointments (1,419). It also had the most scheduled capacity
    (1,900 slots), because the providers who hold clinic on Tuesday have the largest
    combined daily capacity.
  - By booking rate, Monday was highest (76.2%) and Friday lowest (62.3%).

These patterns come from the generator's settings in `config.py`, such as seasonal
demand and department-level No Show rates. They show that the analysis finds and measures
such patterns, not facts about any real clinic.

## KPI definitions

The same definitions are used in SQL, Excel, DAX and this README.

| KPI | Definition |
|---|---|
| Total Appointments | All appointment records, every status |
| Unique Patients | Distinct patients with at least one appointment |
| Completed / Cancelled / No Show Appointments | Appointments with that `appointment_status` |
| Completion / Cancellation / No Show Rate | That status count / Total Appointments |
| Average Wait Minutes | Average `wait_minutes` (check-in to seen), Completed only |
| Average Visit Minutes | Average `visit_minutes` (seen to checkout), Completed only |
| Available Slots | Sum of `provider_schedules.available_slots` |
| Booking Rate | Total Appointments / Available Slots |
| Completed Slot Utilization | Completed Appointments / Available Slots |

Calculation rules:
- **Booking Rate vs Completed Slot Utilization.** Every appointment, whatever its status,
  used a slot when it was booked. Booking Rate therefore counts all statuses, while
  Completed Slot Utilization counts only completed visits.
- **No division by zero.** A rate is blank (SQL `NULL`, an empty Excel cell, DAX
  `DIVIDE`) when its denominator is 0.
- **Overall rates use overall counts.** They are never an average of department
  percentages.
- **Wait time starts at check-in.** It is measured from the actual check-in, which may be
  before the scheduled time.
- **Capacity filters.** Capacity metrics are valid only by date, department and provider,
  not by appointment type or patient group.

## Data model and pipeline

**SQLite database** (`data/processed/healthcare_analytics.db`, rebuilt by `prepare_data.py`)

| Table | Grain | Primary key |
|---|---|---|
| `departments` | department (6) | `department_id` |
| `providers` | provider (12) | `provider_id` |
| `patients` | patient (1,250) | `patient_id` |
| `provider_schedules` | provider clinic day (626) | `schedule_date` + `provider_id` |
| `appointments` | appointment (5,000) | `appointment_id` |

The schema (`sql/01_create_schema.sql`) has:
- foreign keys, including each appointment to its provider's clinic day;
- CHECK constraints on ages, capacities, status values, date formats, time order and
  non-negative durations;
- indexes for the common filters.

**Power BI model** ([POWER_BI_DATA_MODEL.md](powerbi/POWER_BI_DATA_MODEL.md)):
- **Fact tables:** Appointments and ProviderSchedules.
- **Dimensions:** Date, Departments, Providers and Patients.
- **Relationships:** six active, one-to-many, single-direction relationships. Department
  filters both fact tables through Providers.

<details>
<summary>How the synthetic data is generated</summary>

- **Period:** calendar year 2025, weekdays only. Clinic days start at 08:00 with 30-minute
  slots.
- **Departments and providers:** 6 departments with 2 fictional providers each. Each
  provider works fixed weekdays. The number of clinic days is set so that about 75% of
  slots are booked, and a few days have reduced or zero slots.
- **Demand:** busier in winter and early in the week. Department demand, No Show rates
  and cancellation rates differ by design.
- **Completed visits:**
  - patients check in between 20 minutes early and 10 minutes late;
  - waits grow later in the day and on Mondays;
  - visit length depends on appointment type.
- **Cancelled and No Show appointments:** these have no check-in, seen or checkout times.
- **Patients:** Pediatrics sees only patients under 18, and other specialist departments
  see adults. A patient has at most one appointment per day.
- **Settings:** all of them live in `config.py`.

</details>

<details>
<summary>Validation rules applied by <code>prepare_data.py</code></summary>

The only automatic fix is trimming spaces around values. Any other problem stops the
pipeline with a list of problems and example IDs, writes a "failed" quality report, and
leaves the processed folder unchanged.

These rules are checked:
- required columns and values;
- unique primary keys;
- foreign keys;
- each appointment falls on a scheduled clinic day;
- appointment and schedule departments match the provider's department;
- age is 0–120 and the age group matches the age;
- valid status and type values;
- positive provider capacity, and schedule slots between 0 and the provider's capacity;
- bookings never exceed the available slots;
- Completed times are ordered check-in ≤ seen ≤ checkout;
- Cancelled and No Show times are blank.

After loading, the script checks that row counts match the CSV files and runs SQLite
`PRAGMA foreign_key_check`.

</details>

<details>
<summary>SQL views (<code>sql/02_create_analytics_views.sql</code>)</summary>

| View | One row per | Capacity metrics |
|---|---|---|
| `vw_overall_kpis` | whole dataset (with reporting period, unique patients) | Yes |
| `vw_monthly_trends` | month | Yes |
| `vw_department_performance` | department | Yes |
| `vw_provider_performance` | provider | Yes |
| `vw_appointment_type_performance` | appointment type | No |
| `vw_weekday_activity` | weekday (1 = Monday) | Yes |

Each view counts appointments and adds up capacity separately before joining them, so
neither side is multiplied. `analyze_data.py` runs 37 reconciliation checks, for example
that every breakdown adds up to the overall totals, before exporting one CSV file per
view.

</details>

## Setup and run (Windows PowerShell)

Requirements: Windows, Python 3.11 or newer (tested with 3.12), Microsoft Excel and Power
BI Desktop to view the deliverables. Run these from the project folder:

```powershell
# 1. Create and activate a virtual environment, then install the pinned packages
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# 2. Generate the synthetic raw data (data\raw)
python generate_data.py --appointments 5000 --seed 42

# 3. Validate, clean, build SQLite and the quality report (data\processed, data\output)
python prepare_data.py

# 4. Run the SQL analytics, reconciliation and CSV exports (data\output\analytics)
python analyze_data.py

# 5. Create the Excel report (reports\healthcare_patient_flow_report.xlsx)
python create_excel_report.py

# 6. Export the Power BI snapshot (powerbi\data, powerbi\expected_kpis.json)
python prepare_powerbi_data.py

# 7. Run the tests
python -m pytest -q
```

Notes:
- **Blocked activation script:** if PowerShell blocks `Activate.ps1`, run
  `Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned` once, or call
  `.\.venv\Scripts\python.exe` in place of `python`.
- **Which steps change tracked files:**
  - Steps 2–4 write only to `data\`, which Git ignores.
  - Step 6 rewrites `powerbi\data\` with identical content.
  - Step 5 rewrites the tracked workbook. Its content is the same, but the file bytes
    change, so Git shows it as modified. To leave it untouched, use
    `python create_excel_report.py --output <another path>`. If the workbook is open in
    Excel, close it first.
- **Viewing:** open `powerbi\healthcare_patient_flow_dashboard.pbix` in Power BI Desktop,
  and the workbook in Excel. A freshly generated workbook calculates its rate formulas
  when Excel opens it.
- **Other options:**
  - `generate_data.py` accepts `--appointments`, `--seed`, `--patients` and
    `--output-dir`.
  - The other scripts accept input and output paths; run them with `--help`.

## Limitations and design decisions

**Data and scope**
- **Synthetic, not real.** All data is synthetic and the patterns are designed into the
  generator. Results show the method, not real-world findings.
- **One fictional clinic, one year (2025), weekdays only.**
  - There are no public holidays.
  - Insurance categories use US-style labels.
- **Generated time stamps.** Waiting and visit times are simulated, and wait time starts
  at check-in.

**Power BI**
- **Built by hand.** The dashboard was built in Power BI Desktop. The automated tests
  check the data snapshot and files, not the report's internal settings.
- **Refreshing on another computer.** If Power BI cannot find the CSV files, point the
  data source to that computer's `powerbi\data` folder: **Transform data > Data source
  settings**.
- **Accepted design choices.** The dashboard was approved as built. Some formatting
  differs from the original build plan:
  - automatic visual titles;
  - count cards without thousands separators;
  - a monthly line chart whose axis does not start at zero;
  - no on-canvas synthetic-data notice.

  Average Visit Minutes and Cancellation Rate are in the model but not shown on a card.
  These choices are listed in the
  [verification checklist](powerbi/POWER_BI_VERIFICATION_CHECKLIST.md#accepted-design-choices).

**Excel**
- **Rebuilding changes the file bytes.** `create_excel_report.py` writes the same content
  each time, but the file bytes differ (timestamps).
- **Calculated on open.** The tracked workbook is the script's output. Excel calculates
  the rate formulas when it opens the file.
- **Neutral author metadata.** The workbook's author fields are set to "Healthcare Patient
  Flow Analytics". Saving it from Excel would record the Excel user's name instead, so
  regenerate it with the script rather than saving it in Excel.
